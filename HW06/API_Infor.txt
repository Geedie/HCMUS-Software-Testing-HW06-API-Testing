============================================================
FR05 - PRODUCT LISTING AND SEARCH
============================================================

1. Mục tiêu / phạm vi
- Lấy danh sách sản phẩm.
- Tìm kiếm sản phẩm theo tên.
- Có thể kiểm tra dữ liệu trả về của product.
- Product có liên kết với Category thông qua category_id.

2. Base URL
http://localhost:3000

3. API chính


3.1 API CONTRACT / REQUEST

### Endpoint 1 - Product Listing & Search
- Method: GET
- Endpoint: /api/products
- Full URL: http://localhost:3000/api/products
- Authentication: Không yêu cầu
- Query:
  - search: Optional
  - Format: ?search=keyword
- Request Body: Không có
- Ví dụ Request:
  GET /api/products
  GET /api/products?search=iPhone
- Response thành công:
  - HTTP 200
  - JSON array products

### Endpoint 2 - Product Detail
- Method: GET
- Endpoint: /api/products/:id
- Full URL: http://localhost:3000/api/products/:id
- Authentication: Không yêu cầu
- Path parameter:
  - id: Product ID
- Request Body: Không có
- Ví dụ Request:
  GET /api/products/1
  GET /api/products/2
- Response:
  - Product tồn tại: HTTP 200, trả về product
  - Product không tồn tại: HTTP 200, Body = {}

### Endpoint 3 - Category dependency (optional)
- Method: GET
- Endpoint: /api/categories
- Authentication: Không yêu cầu
- Request Body: Không có
- Mục đích: Đối chiếu category_id của product với danh sách category.

GET /api/products

Mục đích:
- Lấy toàn bộ danh sách sản phẩm.
- Tìm kiếm sản phẩm theo tên khi truyền query parameter search.

Query parameter:
- search=keyword
- Optional.

Ví dụ:
GET /api/products
GET /api/products?search=iPhone

4. Authentication
- API GET /api/products KHÔNG yêu cầu Authorization header.
- Có thể test bằng anonymous user.

5. Response từ implementation

Khi KHÔNG có search:
- Server thực hiện:
  SELECT * FROM products
- Trả về toàn bộ products dạng JSON array.

Khi CÓ search:
- Server thực hiện:
  SELECT * FROM products
  WHERE name LIKE '%<searchQuery>%'

6. Product schema từ database

products:
- id: INTEGER, PRIMARY KEY, AUTOINCREMENT
- name: TEXT
- price: INTEGER
- description: TEXT
- imageUrl: TEXT
- category_id: INTEGER

9. Test conditions nên bao phủ

Listing:
- GET không có query parameter.
- Kiểm tra status code.
- Kiểm tra response là array.
- Kiểm tra số lượng sản phẩm.
- Kiểm tra các field:
  id
  name
  price
  description
  imageUrl
  category_id
- Kiểm tra kiểu dữ liệu.
- Kiểm tra dữ liệu thực tế khớp database.

Search:
- Search bằng từ khóa tồn tại.
- Search bằng tên đầy đủ.
- Search bằng một phần tên.
- Search không có kết quả.
- Search với chữ hoa/chữ thường.
- Search với chuỗi rỗng.
- Search với ký tự đặc biệt.
- Search bằng Unicode.
- Search bằng số.
- Search có nhiều ký tự.
- Search với khoảng trắng.
- Search có query parameter không hợp lệ.

10. Điểm quan trọng trong implementation

Search sử dụng SQL string interpolation:

SELECT * FROM products WHERE name LIKE '%${searchQuery}%'

=> Đây là điểm cần kiểm thử đặc biệt về:
- SQL Injection.
- Ký tự đặc biệt.
- Input malformed.

11. API xem chi tiết có thể dùng để hỗ trợ FR05

GET /api/products/:id

Không yêu cầu authentication.

Behavior:
- Nếu id tồn tại: trả về product.
- Nếu id không tồn tại:
  HTTP 200
  Body = {}

Đặc biệt:
- Nếu product.id là số chẵn:
  row.price = row.price.toString()

=> Product id chẵn có price dạng STRING.
=> Product id lẻ có price dạng INTEGER.

Dùng để kiểm tra:
- Schema consistency.
- Data type consistency.
- Response contract.

GET /api/cart

Response:

6. Checkout API

POST /api/checkout

Auth:
- Required.

Body:
{
  "total_amount": 200000,
  "shipping_address": "123 Le Loi, TP.HCM"
}

Implementation lấy:
- userId từ JWT.
- total_amount từ request body.
- shipping_address từ request body.

Server insert:

orders:

- total_amount
- status = "pending"
- shipping_address

Response:

  "message": "Checkout successful",

orders:

- user_id: INTEGER
- total_amount: INTEGER
- status: TEXT DEFAULT 'pending'
- shipping_address: TEXT
- created_at: DATETIME DEFAULT CURRENT_TIMESTAMP

11. Checkout test conditions

Authentication:
- Không có token.
- Token invalid.
- Token expired/không hợp lệ.
- Token của user khác.

Positive:
- Checkout với total_amount hợp lệ.
- Checkout với shipping_address hợp lệ.
- Checkout tạo order thành công.
- Order được tạo với status = pending.
- orderId được trả về.
- Order xuất hiện trong my-orders.

Negative:
- Thiếu total_amount.
- Thiếu shipping_address.
- total_amount = 0.
- total_amount âm.
- total_amount rất lớn.
- total_amount không phải number.
- shipping_address rỗng.
- shipping_address null.
- shipping_address quá dài.
- Request body malformed.
- Request body có field thừa.

Cart:
- Get cart khi chưa có dữ liệu.
- Add product hợp lệ.
- Add nhiều product.
- Quantity = 0.
- Quantity âm.
- Quantity rất lớn.
- Product ID không tồn tại.
- Price không khớp database.
- Name không khớp database.

Data integrity:
- So sánh total_amount request với giá trị thực tế trong cart.
- Kiểm tra server có tính lại total hay không.
- Kiểm tra userId lấy từ token chứ không lấy từ request.
- Kiểm tra order được tạo đúng user.

12. Điểm quan trọng / potential defects trong implementation

A. Checkout không kiểm tra cart

POST /api/checkout chỉ lấy:
- total_amount
- shipping_address

Không đọc userCarts[userId].

=> Có thể checkout ngay cả khi cart rỗng.

B. Checkout không tính lại total_amount

Server tin trực tiếp:
req.body.total_amount

=> Client có thể gửi total_amount tùy ý.

C. Không validate total_amount

Không có validation:
- null
- negative
- zero
- string
- sai format

D. Không validate shipping_address

E. Không có transaction với cart/payment/inventory

Checkout chỉ insert order.

Không có:
- payment
- inventory deduction
- cart clear

F. Cart không nằm trong database

Cart sử dụng in-memory object:

const userCarts = {};

=> Restart server có thể làm mất cart.

G. POST /api/cart không validate product

Có thể gửi object giả:

{
  "id": 999999,
  "name": "Fake Product",
  "price": 1,
  "quantity": 999999
}

và server vẫn thêm vào cart.
